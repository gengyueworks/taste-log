# 收录标准 · Inclusion Criteria

> 这个库的护城河不是「收集得多」，是「每个都看得懂、说得清」。标准定得严，是为了逼出判断。

## 硬门槛：三条全要

一个站至少同时满足下面三条才收（不是「满足其一」，是三条都要）：

1. **第一屏能说出明确的气质判断。**
   打开首屏，能立刻用一句话概括它「是什么气质」——克制、编辑感、科技秩序、温柔工具感……说不出气质的，说明第一屏没有态度，不收。

2. **结构和节奏足够成熟，不是靠单点效果撑。**
   一个惊艳的 hero 动画救不了一整个乱的站。要看信息层级、留白节奏、模块之间的过渡是否自洽。单点亮、整体散的，不收。

3. **有能拿走用的东西。**
   某个模块、某种间距节奏、某个文案语气、某个交互决策——将来做自己的页面时真能用。纯观赏、无可迁移价值的，不收。

## 明确不收

- 只靠流行渐变 + 3D 插画撑起来的「潮」站
- 只有热闹动效、没有结构判断的
- 标准 SaaS 模板脸（一眼能认出是哪个建站工具生成的）
- 链接打不开的（设计再好也按无效处理，先标 dead 不收）

## 一条记录要写到什么程度

不是：

> Kinfolk — 生活方式杂志，很好看。

是：

> **Kinfolk** · 杂志刊物感 · 精华
> 主站气质的母本。图片、文字、留白之间的关系是被「编辑」过的，不是「排」出来的。生活世界感来自内容本身，不靠滤镜和字体撑。能拿走的是它对「少」的克制——一屏只干一件事。

判断要落到**可迁移的具体决策**上，而不是形容词。

## 分类怎么定

从 9 类里选最贴切的（见 README「里面有什么」）：

杂志刊物感 / 长文阅读页 / 产品与工具界面 / 字体工作室 / 设计工作室 / 交互与动效 / 品牌识别 / 策展网络 / 个人主页

一个站可能跨类，选它「最被记住的那一面」。

## 链接有效性

收录前必须能打开。Cloudflare 这类反爬有时会拦自动化探测，但人工能打开的算有效。不确定就先放 `_pending`，不要污染主库。

## 和审美体系的关系

`docs/preferences.md` 是我个人的审美判断体系（白底偏好、排列感、克制科技感 + 编辑感、Kinfolk / Craft 两条母本线、长文阅读页特殊标准）。本标准管「收不收」，那套管「为什么觉得好」。两套一起看，才知道一个站是怎么过审的。
